# 账号、交易、聊天交友与审核

这一层负责所有**需要长期保存、或者要跟着玩家走**的东西：账号、钱、物品、市场、玩家间交易、好友、私信、举报、处罚和审计。
它和世界模拟（分片）是分开的。这两部分的一致性要求完全不同：

| | 世界模拟（分片） | 账号/经济/社交（meta） |
|---|---|---|
| 存在哪 | 内存 + 每 30 秒快照 | PostgreSQL（单机可用 SQLite），每次操作落盘 |
| 丢了会怎样 | 回到几十秒前的世界，问题不大 | 丢钱、复制物品、聊天记录消失，不可接受 |
| 并发模型 | 每个分片单线程 tick | 数据库事务（可串行化重试） |
| 扩展方式 | 按空间切 | 按账号 id 路由到副本，状态全在库里 |

**核心原则：世界里的实体没有价值，只有物品有价值。** 生物可以随便生、随便死、随便在分片之间迁移、随着快照回滚。只有被“收集”进背包变成物品之后，它才进入有账本、有事务保护的世界。两边之间的转换都按“宁可丢、不可复制”的方向设计（见下文“收集与放生”）。

## 架构

```
 浏览器 ──wss── 网关 ──┬── 分片（世界）
                      │
                      └── meta 副本 0 ─┐
                          meta 副本 1 ─┼── PostgreSQL
                          meta 副本 … ─┘
                            ↑    ↑
                     副本之间互连（转发推送、共享在线名单）
```

- **meta 进程**（`src/meta/meta-node.js`）：无状态服务，可以开多个副本，全部连同一个 PostgreSQL。
- **路由**：每个账号有一个“主副本” = `账号 id % 副本数`。网关把这个账号的请求都发给它的主副本，所以按账号做的限速是准确的。主副本挂了，请求会改发给其他活着的副本（状态都在库里，任何副本都能处理），只有实时推送要等主副本恢复。
- **在线状态和推送**：玩家连上网关后，网关告诉其主副本“账号 X 在我这里的连接 c 上”。任何副本要给 X 推送（私信、好友上线、交易更新、成交通知、处罚），都转发给 X 的主副本，由主副本推给网关、再推给浏览器。所有副本互相同步“谁在线”。
- **网关**：握手时用会话 token 认证一次，之后转发**白名单内**的调用（`src/meta/methods.js`），并在每个调用上盖上服务器认定的账号 id。客户端永远不能自己声明“我是谁”，也调不到内部方法（发币、改角色、收集入账等）。
- **分片**：每分钟把各账号谱系的存活数量报给 meta 发奖励；处理“收集”和“放生”请求。

单机运行（`npm start`）时自动起一个 meta 进程，数据存在 `data/meta.db`（SQLite）。生产环境设 `DATABASE_URL=postgres://...`，可以开多个副本（`--meta 2`，或用 `scripts/gen-cluster.mjs`）。

## 账号（`src/meta/accounts.js`）

- **注册/登录**：用户名 2–20 个字（中文、字母、数字、下划线，不区分大小写），密码至少 8 位，用 **scrypt** 加盐哈希存储。
- **登录失效立即生效**：改密码、“退出所有设备”、用恢复码重置之后，这个账号其他已打开的连接会被立刻断开（不会让盗号者的页面继续交易），然后以游客身份重连。
- **两步验证不能被偷到会话的人关掉**：关闭需要验证码；已开启时也不能直接“重新设置”（那等于不用验证码就关掉了）。
- **会话**：登录后发一个随机 token（客户端存在 localStorage），**库里只存它的 SHA-256**，库泄露也拿不到可用的 token。有效期 30 天，可以查看登录设备、“退出所有设备”。改密码会让所有旧会话失效。
- **两步验证（TOTP，RFC 6238）**：兼容 Google Authenticator、微软验证器等。同一个验证码不能用两次（防重放）。
- **恢复码**：注册时一次性给 8 个，每个只能用一次，用来在忘记密码时重置（同时会关闭两步验证、登出所有设备）。没有邮箱/短信依赖。
- **防批量注册（工作量证明）**：注册前浏览器要先算一道题（服务器签名、10 分钟内有效、只能用一次），默认难度（`POW_BITS=16`）在普通浏览器里中位数约 1 秒（实测 8 次：0.05–4.4 秒）。对正常玩家几乎无感，批量注册一万个小号就要花上万秒的计算。**说实话它挡不住专门优化过的刷号程序**（本地代码比浏览器快约百倍），只是提高门槛；真要防，需要接入短信、邮箱或第三方人机验证。
- **防爆破**：10 分钟内，同一 IP 失败 10 次、或同一 IP 对同一个名字失败 10 次，这个 IP 就被暂时拒绝。**不会因为别人乱试密码就把账号本人锁在外面**：一个名字 10 分钟内被试错 100 次以上时，只拒绝已经对它试错过的 IP，本人从自己的网络照常能登录。改密码时输错原密码也计数（防止偷到会话的人暴力猜原密码）。同一 IP 每小时最多注册 5 个号（`REGISTER_PER_IP_HOUR`）。这些计数和“两步验证码只能用一次”的记录都存在数据库里，所有副本共用、重启不丢；IP 只以带密钥的哈希形式入库。
- **角色**：`player` / `mod`（版主）/ `admin`（管理员）。
- **世界身份**：登录玩家的世界身份就是账号 id（`< 2^30`），游客是签名的随机 id（`[2^30, 2^31)`）。两个范围不重叠，游客永远冒充不了账号的谱系。同一账号在同一网关再开一个页面，旧页面会被挤下线（关闭码 4004）。
- **游客照样能玩**：不登录也能进世界、播种、聊天，只是不能收集、交易、加好友、私信。游客的名字前面会自动加上“游客·”，没法在聊天或排行榜里冒充注册玩家。

## 经济（`src/meta/ledger.js`, `src/meta/economy.js`）

### 复式记账

- 所有的钱都在 `balances` 表里，每一笔变动都在 `ledger` 表里记一行（从谁、到谁、多少、原因）。
- 两个系统账户：`MINT (-1)` 负责发行（新账号的 100 启动金、奖励），`SINK (-2)` 负责回收（手续费、放生费）。**所有余额加起来永远是 0**，不可能凭空多出钱。运维后台的“经济”面板实时检查这一点。
- **每一笔都有唯一的幂等键**（如 `buy:<挂单>:pay`、`life:<世界>:<分钟>:<分片>:<账号>`），同一个键只会生效一次。网络重试、进程重启后重放都不会多扣或多发。
- 扣款是条件更新（`amount >= 扣款额` 才扣），余额不可能变成负数。
- PostgreSQL 上事务用可串行化隔离级别，遇到冲突（40001/40P01）自动重试；SQLite 上所有写操作串行执行。

### 物品

- 物品有唯一的来源键（`cap:<世界>:<实体 id>`），同一个生物不可能被收集成两件物品。
- 物品有“托管锁”：挂单时被锁住，锁住的物品不能再挂、不能拿去交易、不能放生。一件物品同时只能在一处托管。
- 每次转手都写进 `item_log`，可以追溯物品的完整历史。

### 市场

- 卖家挂单（物品被锁），买家购买：在**一个事务里**完成“挂单状态翻转（只有一个买家能成功）→ 付款给卖家 → 5% 手续费进 SINK → 物品转给买家”。
- 每人最多同时挂 50 单。卖家会实时收到“已售出”通知。
- 手续费是销毁的，用来抵消奖励带来的通胀（后台能看到累计发行和累计回收）。

### 玩家间交易（P2P）

- 一方发起，双方各自摆上物品和金额。**任何一方改动出价，版本号 +1，双方的确认都清空。**
- 确认时要带上自己看到的版本号，版本对不上就失败。**成交的一定是你确认时看到的内容**，没有最后一秒偷换。
- 双方都确认后，在一个事务里重新检查物品归属和余额，然后一次性交换。如果其间物品已经卖掉或钱已经花掉，交易不会执行，确认被清空，双方需要重新确认。
- 被屏蔽的人不能对你发起交易；屏蔽对方会自动取消进行中的交易。每人最多 5 个进行中的交易，每边最多 12 件物品。

### 收集与放生（世界 ↔ 物品）

**收集**（`🫙` 工具，点击自己谱系的生物）：

1. 网关检查：已登录，目标在你的视野内，今天的收集次数没用完（每天 50 次）。
2. 拥有该位置的分片检查生物属于你，然后把它从世界里移除，返回它的基因数据。
3. 网关把数据交给 meta 入库（带唯一来源键，网络抖动时会自动重试）。

如果第 2 步之后网关崩溃，最坏的结果是这个生物消失了而你没拿到物品，**不会出现两件物品**。如果分片崩溃后从快照里“复活”了这个生物、又被收集一次，来源键相同，库里只会认第一次。

**放生**（背包 → 放生 → 点击地图）：先在 meta 里消耗物品并扣 5 枚放生费，再让分片按物品里的基因生成一个新生物（同一个放生键只生成一次）。物品里只存基因、不存能量，所以买卖物品不能往世界里“注入能量”；分片还会把基因夹回正常范围，被篡改的数据也造不出怪物。

游戏接入：实现可选的 `captureEntity(region, e, pid)` 和 `spawnFromItem(region, data, x, y, pid)`，见 [game-interface.md](game-interface.md)。

### 奖励

分片每分钟统计每个账号在本分片上存活的后代数量 n，发 `min(3, floor(√n))` 枚（`REWARD_CAP`）。开根号和上限是为了让“刷数量”收益很低。幂等键包含世界 id、时间段、分片和账号，同一时段重复上报只算一次。

## 社交（`src/meta/social.js`）

- **在线状态只给好友看**：按名字查人只返回 id 和名字，不暴露对方是否在线。
- **好友**：按用户名申请，对方接受；如果对方也申请过你，自动成为好友。好友上限 500。好友上下线会实时提示。
- **私信**：存在库里，离线也能收到，有未读数，可以查历史。
  - **隐私设置**：所有人 / 仅好友 / 不接收。
  - **屏蔽**：双向生效，对方的私信和交易请求都会被拒，好友关系一并解除。
  - **限速**：每人每分钟最多 20 条；每小时最多主动联系 10 个陌生人（防群发骚扰和广告）。
- **举报**：举报私信骚扰时，**证据由服务器从库里取**（双方最近 30 条私信），举报人无法伪造聊天记录。每小时最多 20 次举报。

## 自动审核（`src/meta/moderation.js`）

世界聊天和私信都走同一套规则，每条消息都会检查，不调用任何外部服务：

| 规则 | 处理 |
|---|---|
| 屏蔽词（`BLOCKLIST` 文件） | 替换成 `*`，消息照发 |
| 外部链接（不在 `ALLOW_DOMAINS` 里） | 拦截。物品一旦值钱，钓鱼链接就是头号骗局 |
| 联系方式 / 场外交易（加微信、QQ、长串数字、telegram…） | 发给**非好友**时拦截（防“加我微信便宜卖”的场外诈骗）；好友之间不拦 |
| 60 秒内重复同一句话 3 次 | 拦截（刷屏） |

被拦截一次记一次违规，**10 分钟内 5 次违规自动禁言 10 分钟**：禁言写进账号（换网关、重新登录都还在）、推送给本人，并写入审计日志。游客的自动禁言只在当前网关有效。

规则故意做得简单、确定，不会误杀正常聊天。更细的判断交给玩家举报和人工处理。如果需要接入第三方内容审核服务，在 `Moderator.check` 里加，或者异步扫描 `messages` 表。

## 人工审核与运维后台

`/admin` 支持两种登录方式：

- **管理人员账号**：用游戏账号登录（密码 + 两步验证），角色必须是 `mod` 或 `admin`。**建议所有管理人员都开启两步验证。**
- **`ADMIN_TOKEN`**：超级管理员口令，用于第一次把某个账号设成管理员，以及应急。

| 能力 | 版主 | 管理员 |
|---|---|---|
| 查看集群、聊天记录、玩家、举报、账号、经济、审计日志 | ✅ | ✅ |
| 禁言 / 解除禁言、踢出、处理举报 | ✅ | ✅ |
| 封号（账号级，立即断开所有连接，会话全部作废） | — | ✅ |
| 改角色、搬迁区块、开关负载均衡、旧式封禁（身份/IP） | — | ✅ |

**每一个管理操作都写进审计日志**：谁、什么时候、对谁、做了什么、理由。版主无法删除审计记录。

第一次设置管理员：

```bash
# 先在游戏里注册账号（比如叫 boss），查到它的 id：
curl "https://你的域名/admin/api/meta/account?name=boss" -H "authorization: Bearer $ADMIN_TOKEN"
# 设为管理员（把 1 换成上面查到的 id）：
curl -X POST https://你的域名/admin/api/meta/role -H "authorization: Bearer $ADMIN_TOKEN" \
     -H 'content-type: application/json' -d '{"id": 1, "role": "admin"}'
```

之后这个人就可以在 `/admin` 用自己的账号登录，再在后台“账号”面板里给别人设版主。

## 和世界、分区、运维的衔接

每一条都有自动测试（`test/meta.test.js`），或者用真实浏览器 / 真实集群验证过。

| 场景 | 行为 |
|---|---|
| **游客注册或登录** | 游客时期培育的后代自动归入账号：网关通知所有分片把这个游客 id 名下的生物改成账号 id，正在跨分片迁移、或者正在随区块搬迁的生物也会被改到。游客 id 由签名 token 证明，冒充不了别人的谱系。改完之后，这些生物可以收集、可以拿奖励 |
| **镜头跨区（分区网关）** | 同一个账号在新旧两个网关上短暂同时在线：在线状态不会闪成“离线”，私信送到新连接，重复的推送在客户端去重。还没收到回复的调用（比如正在注册）会让旧连接多保留最多 10 秒，等回复到了再断开。显示恢复码的界面不会被切区打断 |
| **聊天记录里的禁言 / 封禁** | 后台“聊天记录”“查找玩家”里对某个 pid 的禁言或封禁，如果这个 pid 是账号，账号本身也会被禁言或封禁（私信同样受限，换设备、重新登录都还在）。在“生效中的处罚”里解除时，账号上的也一起解除 |
| **被封账号以游客身份回来** | 匿名游客本来就拦不住，可以设 `GUESTS_CAN_CHAT=false`：游客能看能玩，但只有登录玩家能聊天 |
| **meta 副本挂掉** | 调用自动改发给其他副本（数据都在库里，任何副本都能处理）；离线期间发的私信存在库里，上线后能看到；其他副本会先把它负责的账号当作离线，等它恢复后网关重新报到，在线状态和实时推送都会恢复 |
| **整个集群重启** | 会话、余额、物品、账号名下的谱系（分片快照里）都保留，玩家刷新页面后直接回到原账号 |
| **不启用账号系统**（`--meta 0`，或不设 `META_URLS`） | 游戏照常运行；客户端隐藏账号相关按钮和收集工具；调用返回“没有启用账号系统” |

## 实测

- **端到端测试**（`test/meta.test.js`，SQLite 和 PostgreSQL 各跑一遍）：2 个 meta 副本、2 个网关，两个玩家在不同网关、账号在不同副本上，覆盖注册、会话、好友、上下线推送、私信（实时到达）、隐私、屏蔽、举报证据、收集、放生、市场买卖、P2P 交易、奖励幂等、世界聊天自动禁言、版主/管理员权限、封号立即断线、审计日志。
- **经济并发测试**（`test/economy.test.js`）：12 个账号同时乱序做几百个抢购、交易、转账、重复奖励，事后核对：没有负余额，每个账户余额 = 账本流水之和，所有余额之和 = 0，没有物品同时处于两个托管，每个挂单最多卖出一次。
- **浏览器测试**：两个真实浏览器完成注册（恢复码）→ 播种 → 收集 → 挂单 → 加好友 → 私信 → 对方购买（卖家实时收到成交通知）→ 发起交易，0 个页面错误。
- **压测**（`bench/meta-load.js`，4 核机器上同时跑着分片、2 个网关、2 个 meta 副本、PostgreSQL 和机器人）：

| 并发账号 | 吞吐 | 延迟 p50 / p90 / p99 |
|---|---|---|
| 500（每人每秒 2 次调用） | 968 次/秒，实时推送 1.86 万条 | 2.1 / 5.0 / 16 ms |
| 1500（每人每秒 2 次调用） | 2898 次/秒，实时推送 5.6 万条 | 13 / 43 / 95 ms |

调用的组合：30% 私信，15% 查钱包，15% 浏览市场，10% 好友列表，10% 未读数，其余是历史记录、交易、查人、好友申请。注册 1500 个账号用了 25 秒，主要花在 scrypt 哈希上（这是故意的，用来拖慢暴力破解）。

## 10 万人在线时这一层要多少资源（推算）

玩家大部分时间在玩世界，社交/交易调用远比世界消息稀疏。假设平均每人每 20 秒一次调用：10 万人 ≈ 5000 次/秒。

- **meta 副本**：上面的压测里，一个 4 核机器上同时跑着所有东西，就能做到约 3000 次/秒。生产环境建议 **4 个副本**，分在 2 台机器上，留一倍余量。
- **PostgreSQL**：一台 8–16 核、NVMe 磁盘的主库，加一个流复制备库（用于故障切换和备份）。写入主要是私信和账本，每秒几千行。`messages` 表会一直增长，建议按月分区，或者定期把半年前的私信归档。
- **注册高峰**：scrypt 每次约 50 ms CPU，开服时每秒 1000 个注册需要约 50 个核秒。可以临时加 meta 副本，或者调低 scrypt 参数（安全性会降低）。

## 数据保留与升级

- **自动清理**（每个 meta 副本每 10 分钟一次，分批删除，不会长时间锁表）：过期会话；一小时前的登录失败计数；超过 `MESSAGE_RETENTION_DAYS`（默认 365 天，设 0 表示永久保留）的私信。举报时附带的证据是单独存在举报记录里的副本，不受影响。**钱、物品、账本、交易记录、审计日志永远不会被自动删除。**
- **表结构升级**：数据库里有 `schema_version` 表。新版本启动时自动按顺序执行还没执行过的升级（PostgreSQL 上用锁保证多个副本同时启动时只执行一次）。老库会被当作版本 1 直接升级，已有数据保留（测试覆盖了“用旧版本建的库 → 新版本打开”）。升级前照常先备份。

## 已知限制和后续可以做的

- **控制面高可用**：0 号分片（协调者 + 旧式处罚列表）是单点，挂掉期间不能搬区块、不能做旧式封禁（账号封禁走 meta，不受影响），会被自动拉起。
- **备份**：用 `scripts/backup.sh` 定时备份，并用 `BACKUP_UPLOAD` 传到另一台机器或对象存储（见 [deploy.md](deploy.md) 的“备份与恢复”）。需要做到“丢失不超过几秒”的话，在 PostgreSQL 上另外开 WAL 归档或流复制。**库里是玩家的全部财产，丢了没法补。**
- **身份证明**：现在只有用户名 + 密码 + 两步验证，没有邮箱或手机号验证。如果需要防止批量注册小号，可以接入短信、邮箱、第三方登录，或者人机验证。
- **反洗钱 / 刷金**：后台“可疑资金流向”面板会列出近 24 小时从其他玩家收钱最多的账号（标出“大部分来自新注册账号”的情况），以及同一注册 IP 下的账号群和群内互转金额。这些只是提示，不会自动处罚，由管理员判断。更复杂的模式（多跳洗钱、借市场挂单高价互买）还需要人工看账本或后续加规则。
- **未成年人保护、实名、支付合规**：如果允许真钱充值或提现，这些都是法律要求，需要在上线前单独处理。当前设计**没有真钱入口**。
