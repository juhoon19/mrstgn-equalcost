# 架构

目标：**参与人数没有上限**，而且人越多越热闹，而不是越卡。

“任意数量的人”在实时游戏里会撞上三堵墙，这套架构分别用一层去解决：

| 墙 | 为什么会撞 | 对应的层 |
|---|---|---|
| 连接与带宽 | 每个玩家都要持续收数据；单进程能维持的 socket 和出口带宽有限 | **网关层**：无状态，水平扩展 |
| 模拟算力 | 世界越大、生物越多，单核算不动 | **分片层**：世界按区块切成矩形块，各进程并行 |
| 同一位置挤满人 | 一千人盯着同一块，所有流量都指向它 | **编码一次 + 扇出**：分片对每个区块只编码一次，观众成本落在网关 |

## 1. 世界与区块

- 世界是 `chunksX × chunksY` 个正方形区块（默认 24×24，每块 256 单位）。
- 每个区块有实体列表和一张化学场网格（16×16 × 3 通道：营养/废物/信号）。
- **区块 → 分片**的归属由 `Topology` 纯函数计算：把区块网格切成 `sx × sy` 个尽量正方形的矩形块。每个进程拿同样的参数算出同样的结果，不需要协调服务。

## 2. 分片（shard-node.js）

每 50ms（20 Hz）一个固定步长：

1. 重建空间哈希（本地实体 + 邻居发来的幽灵）。
2. 游戏逻辑 `game.step()`：运动、感知、代谢、分裂、捕食……
3. 化学场：每 2 tick 做一次扩散 + 反应（显式五点差分，边界一圈从邻居区块或幽灵边读取）。
4. 重新归桶：实体离开本区块 → 进入同分片别的区块，或打包**迁移**给新主人分片（id 不变，基因一起带走）。
5. 给每个邻居分片发**幽灵**：离接缝 48 单位以内的实体（只读）+ 边界区块的化学场边缘行。
6. 每 2 tick（10 Hz）为**有人订阅的**区块编码网络帧；每 20 tick 编码化学场（下采样到 8×8）；每 20 tick 发世界概览和排行榜。

### 跨分片一致性规则

- **唯一主人**：实体只属于包含它坐标的区块的主人分片。
- **幽灵只读**：分片只能修改自己的实体。碰撞推开只改自己那一半（对面分片对它的实体做对称计算），吃掉/杀死只能作用在本地实体上。
- **一 tick 延迟**：幽灵和场边缘是邻居上一 tick 的状态。对 20Hz 的软体碰撞和化学感知来说不可察觉。
- **迁移不丢**：邻居连接断开时，要迁出的实体先放在发件箱，连接恢复后补发。

### 时间膨胀（借鉴 EVE Online）

分片算不完一个 tick 时不跳帧，也不放大 dt（放大 dt 会让物理爆炸），而是让模拟整体变慢。`tidi` = 实际完成的 tick / 应完成的 tick，随排行榜广播给客户端显示。加分片即可恢复。

## 3. 快照：编码一次，扇出 N 次（snapshot.js）

每个区块维护“上次发出的状态”`lastSent`，每个网络帧产生一条 `S_CHUNK`：

- **关键帧**：区块内所有实体的完整记录（订阅时强制一次，之后每 30 帧一次）。
- **增量帧**：消失的 id（排序后差分编码）、新出现的实体（完整记录）、移动的实体（`id差<<2|标志`、位置差 zigzag varint，半径/等级只在变化时附带）。
- 位置在区块内量化为 1/8 单位的 uint16，移动一帧通常 1 字节/坐标。

增量是相对**同一流的上一帧**，而不是相对每个客户端的确认（Quake/Gaffer 式）。WebSocket 可靠有序，所以这是安全的，而且**所有观众共享同一份字节**。代价是新观众或落后的观众要从关键帧追上，这由网关缓存解决。

## 4. 网关（gateway-node.js）

- **兴趣管理**：客户端上报视口矩形和想要的**质量档** → 网关算出视野 + 96 单位边距内的区块（`Topology.viewChunks`，客户端用同一个函数，两边集合一致）。
- **三级细节（LOD）**：
  1. 高档（放大看时）：10 Hz 实体流，最多 30 个区块；
  2. 低档（缩放 < 0.9 时）：同一区块的另一条 2.5 Hz 实体流，最多 80 个区块，实体带宽约为高档的 1/2.5；
  3. 再远：只收全世界概览（每区块人口/主色/营养）。
  每个档位都是独立的“关键帧 + 增量”流，分片对每个区块每个档位只编码一次。
- **引用计数订阅**：第一个看某区块的客户端让网关向分片订阅，最后一个离开后保留 5 秒再退订（来回拖动不抖动）。分片只知道“有几个网关”，不知道有几个人。
- **缓存链**：网关为每个订阅的区块保留“最近关键帧 + 之后所有增量”。新观众立刻收到整条链，无需等下一个关键帧。
- **背压**：客户端 socket 积压超过 512KB 时，把它的区块标为“需重同步”并停止给它发增量；恢复后从缓存链追上。慢网速的人不会拖累别人，也不会让服务器内存无限增长。
- **合并发送**：同一 tick 发给同一客户端的几十条消息打包成一条 `S_BATCH`。这是单网关从约 660 人（CPU 90%）提升到 1000 人（CPU 37%）的关键。
- **输入卫生**：令牌桶（200 突发、100 条/秒）、每种工具的冷却、坐标合法性、只能在自己看得见的区块操作、单消息 4KB 上限、单 IP 连接数上限、聊天清洗控制字符。
- **身份**：匿名，HMAC 签名的 token（`pid.签名`），换网关/断线重连保持同一 pid，也就保住了自己的谱系。

## 5. 客户端副本（ClientWorld，浏览器与机器人共用）

两层结构：

1. 每个区块一份**流镜像** `c.ents`：严格按该区块的流应用增量。
2. 每个实体一份**渲染实体**，归属于“关于它信息最新的那个区块”。每帧都带分片的毫秒时钟。

为什么需要第 2 层：区块流之间没有全局顺序。比如订阅新区块时网关回放的缓存链可能比相邻区块的实时帧老 1~2 秒；跨分片交接时两个分片的帧到达顺序不确定。若直接“最后到达者为准”，旧链会把实体抢回旧区块，随后旧区块的“删除”再把它删掉——压测中真实出现过这种丢实体问题（见 `test/unit.test.js` 里的回放测试）。规则“时间戳更新者为准 + 删除留墓碑”彻底解决了它。

渲染时每个实体从上一位置到新位置在一个网络间隔（100ms）内插值。

## 6. 互动如何扩展到任意人数

- **光标**和**聊天**也按空间走：它们被发送到坐标所在的分片，作为那个区块的事件广播，只有看着那里的人会收到。一万人在线时，你只看到附近的人。每区块最多显示 32 个光标。
- **工具效果**（投营养、播种等）同样是区块事件，附近所有人看到涟漪。
- **排行榜**：每个分片统计各谱系存活数，网关汇总前 15 名。

## 7. 持久化与故障恢复

- 每个分片每 `SNAPSHOT_EVERY` 秒（默认 30）把自己的区块（化学场 + 实体 + 基因 + id 计数器 + 时钟）写到 `DATA_DIR/shard-<id>-of-<n>.bin`（先写临时文件再原子改名）。收到 SIGTERM 时写最终快照再退出。
- 启动时如果有**同一分片号、同样分片数和世界尺寸**的快照就恢复，否则新建世界。改了分片数，旧快照会被忽略。
- `launch.js` 把集群密钥和玩家 token 密钥存在 `DATA_DIR/secrets.json`，重启后玩家身份（和谱系归属）不变。
- 分片崩溃：`launch.js`/Docker 自动重启它；网关断线重连、重新订阅，客户端从关键帧重新同步，玩家不掉线。实测强杀一个分片后 30 个客户端全部保持连接，0 失步。

## 8. 扩容手册

| 现象 | 指标 | 动作 |
|---|---|---|
| 连接/带宽满 | 网关 `/metrics` 的 `bytesOutPerSec`、CPU、客户端 RTT | 加网关（`--scale gateway=N`），负载均衡自动分流 |
| 模拟变慢 | 客户端“时间流速” < 100%，分片 `tickMs` 接近 50 | 加分片（改 `TOPOLOGY.shards`，重启分片），或降低 `maxCellsPerChunk` |
| 单人带宽过高 | 机器人报告 `KB/s/bot` | 降低实体密度、`MAX_CHUNKS`、`NET_EVERY`、`FIELD_NET_RES` |

粗略估算：

- **网关**受网卡带宽限制，而不是 CPU。800 人时对网关做 CPU 剖析：76% 空闲，忙的时间里绝大部分是内核 `writev` 发包（12.5%），JS 逻辑不到 5%。所以 1 Gbps 网卡 ≈ 4000–6000 人（每人 20–30 KB/s）。人再多就再加一台网关机器。
- **分片**受 CPU 限制：每个分片进程（1 核）≈ 1.5–2 万个活跃实体（演示游戏约 2.3 µs / 实体 / tick）。

## 9. 已知边界与下一步

- **静态分区**：分片边界固定。热点（所有人挤在一个角落）会压垮一个分片。下一步是像 SpatialOS 那样按负载动态移动区块归属（区块状态已经自包含，迁移一个区块 = 冻结 → 序列化 → 改拓扑 → 恢复）。
- **分片间不锁步**：邻居各自计时，交界处有一 tick 的不对称。对演化模拟无影响；若你的游戏需要严格确定性，可以加 tick 屏障。
- **崩溃恢复的精度**：进程被强杀时，分片从最近一次定期快照（默认 30 秒）恢复；这段时间内跨边界迁移的实体可能丢失或重复一份。正常停止（SIGTERM）会先写最终快照，没有这个问题。
- **uWebSockets.js**：网关换成 uWS 可以再提高数倍单进程连接数，协议不变。
